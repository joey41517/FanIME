# FanIME 架構規劃

> 目標：沿用超注音「中英為主 + 扇形叫出符號表」的操作方式，補上好用的日文（羅馬拼音 + 漢字轉換）和韓文。
> 原則：clean-room。只參考操作方式，不使用超注音的程式碼、圖示或資料。
> 觀察紀錄：見 `docs/recon/recon-chaozhuyin.md`

## 1. 開發環境

| 項目 | 選擇 |
|---|---|
| 語言 | Kotlin |
| IDE | Android Studio 262（JBR 25） |
| compileSdk / targetSdk | 37 |
| minSdk | 26（Android 8.0）。實際只在 S25（Android 16）上測試 |
| 測試裝置 | Samsung SM-S9310，透過 USB adb 測試，不使用模擬器 |
| 權限 | **不申請網路權限**。輸入法看得到所有打的字，資料一律只存在手機本機 |

## 2. 整體結構

```
FanImeService (InputMethodService)
 ├─ KeyboardView（自繪 Canvas View，負責所有按鍵的繪製和觸控）
 │   ├─ Layout：注音 / 英文 / 數字 / 符號表（JSON 定義）
 │   └─ FanOverlay：扇形選單（同一個 View 上的疊加層）
 ├─ CandidateBar：候選字列
 ├─ InputEngine（介面）
 │   ├─ EnglishEngine：直接輸出
 │   ├─ ZhuyinEngine：libchewing（JNI）
 │   ├─ KoreanEngine：兩套式組字（Kotlin 自己寫）
 │   └─ JapaneseEngine：羅馬拼音 → 假名 → 漢字（Mozc 或替代方案）
 └─ Settings：顏文字清單編輯、扇形設定（DataStore）
```

**為什麼用自繪 View，不用 Jetpack Compose**：在輸入法服務裡用 Compose 要自己處理 lifecycle，觸控延遲也比較難控制。扇形需要精準追蹤按住和拖曳的手勢，用自繪 View 最直接。

**InputEngine 介面**（每種語言實作一份）：
```kotlin
interface InputEngine {
    fun onKey(key: Key): EngineResult      // 回傳：要上屏的文字、組字中的文字、候選字
    fun selectCandidate(index: Int): EngineResult
    fun reset()
}
```

## 3. 鍵盤配置

**主鍵盤（注音）**：沿用標準注音排列，4 列，加上底列。

底列：`中英` | `扇形鍵` | `標點` | `空白` | `句號` | `ㄦ` | `⌫` | `⏎`

- `中英`：在注音和英文 QWERTY 之間切換（最常用）
- 英文鍵盤：**最上面一列是數字**，底列配置相同，同樣有扇形鍵

**標點鍵（點一下再往某個方向快滑、放開）**：每個語言各有 4 個最常用的標點。

方向是**斜向**的，鍵上的標籤照方向排成 2×2。實測超注音後確認：

| 鍵盤 | ↖ | ↗ | ↙ | ↘ | 輕點 | 句號鍵 |
|---|---|---|---|---|---|---|
| 注音 | ？ | 、 | ， | ！ | ，（推測） | 。 |
| 英文 | ? | :（超注音原本是 `@`） | , | ! | , | . |

- 實測時正上方被判定成 ↖、正右方被判定成 ↘，所以判斷方式應該是看落在哪個象限，不是只認嚴格的斜角

**數字鍵盤**：使用頻率很低，英文鍵盤的數字列就夠用了。

- 輸入框是電話欄位（`TYPE_CLASS_PHONE`）或數字欄位（`TYPE_CLASS_NUMBER`）時，自動切換成數字鍵盤，排在最後才做
- 不放在扇形裡

## 4. 扇形（核心功能）

### 手勢
| 操作 | 結果 |
|---|---|
實測超注音：**不需要先按住**，按下後立刻往某個方向滑就會觸發。按住約 1 秒才畫出扇形，只是給還不熟方向的人看的提示。

| 操作 | 結果 |
|---|---|
| 按下後直接往某個方向滑、放開 | 立刻開啟該方向的選項（熟練後的主要用法） |
| 按住不動超過 `hintMs`（預設約 1 秒） | 畫出扇形提示 |
| 在中心附近放開（距離小於 `deadZone`） | 取消 |
| 拖曳過程中 | 扇形已經顯示的話，即時高亮目前指到的選項 |
| 輕點 | 不做事 |

### 選項判斷
- 以扇形鍵中心為原點，計算手指的角度 θ 和距離 r
- 扇形範圍：從正上方往左偏 15° 到正右方（約 105°），平均分給 N 個選項
- r 小於 `deadZone` 時視為取消；r 大於 `deadZone` 時，依 θ 落在哪個扇區決定選項
- 選項清單由設定決定，數量 4–8 個

### 預設選項（從左上到右）
| # | 選項 | 內容 |
|---|---|---|
| 1 | 半 | 半形符號表 |
| 2 | 全 | 全形符號表 |
| 3 | 😀 | Emoji（使用 androidx `EmojiPickerView`） |
| 4 | (^^) | 顏文字表，**清單可自行編輯** |
| 5 | 한 | 韓文鍵盤 |
| 6 | あ | 日文鍵盤（羅馬拼音） |

## 5. 符號表

- 用 JSON 定義（`assets/tables/*.json`），每頁 8 欄 × 4 列，可以有多頁
- 底列：`返回` | 該表專屬的鍵 | `⌫` | `釘選`
- **釘選**：沒釘選時，點一個符號就自動回到原本的鍵盤；釘選後會留在符號表，方便連續輸入。**預設為釘選**，因為使用者幾乎都是用釘選
- 半形、全形表的內容自己整理（用 Unicode 的半形與全形字元），不照搬超注音的排列

## 6. 各語言引擎

| 語言 | 引擎 | 授權 | 難度 | 備註 |
|---|---|---|---|---|
| 英文 | 直接輸出 | — | 低 | 之後可加自動大寫 |
| 注音 | **libchewing**（新酷音） | LGPL-2.1 | 中 | C 函式庫，用 NDK + JNI 呼叫，內建詞庫和智慧選詞 |
| 韓文 | 自己寫兩套式組字 | — | 低 | 用 Unicode 韓文音節的公式組字，不需要詞庫 |
| 日文 | **Mozc** | BSD-3 | **高** | Google 日本語入力用的核心，品質最好，但 Android 版的建置很複雜（Bazel） |

**LGPL 注意事項**：自己使用沒有問題。如果之後要公開發布，libchewing 要以動態連結的方式使用，並附上它的原始碼或取得方式。

**日文的替代方案**：如果 Mozc 太難整合，先做「羅馬拼音 → 假名」加上簡易的字典轉換（例如 SKK 字典），之後再換成 Mozc。

## 7. 開發階段

| 階段 | 內容 | 完成時可以做到 |
|---|---|---|
| **0. 骨架** | 建立專案、InputMethodService、英文 QWERTY、空白／Enter／刪除；用 adb 裝到手機上 | 手機上可以切換到 FanIME 打英文 |
| **1. 扇形 + 符號表** | 扇形手勢、半形表、全形表、Emoji、數字鍵盤自動切換 | 英文加符號已經能日常使用 |
| **2. 注音** | 編譯 libchewing、注音鍵盤、候選字列、中英切換 | **最小可用版**：可以取代超注音的日常使用 |
| 2.5 英文字詞提示 | 前綴補完（例如打 `ca` → can / came / can't），詞庫用 AOSP LatinIME 的英文詞表（Apache 2.0），之後再加學習常用字 | 英文打字更快；自動修正拼錯、預測下一個字屬於進階功能，往後排 |
| 3. 顏文字 | 顏文字表 + 設定頁編輯清單 | |
| 4. 韓文 | 兩套式鍵盤 + 組字 | |
| 5. 日文 | 羅馬拼音 + 漢字轉換 | 解決最大的痛點 |
| 6. diff | 跟超注音比較功能和手感，列出還缺什麼 | |

**階段 2 是最難的一步**，要處理 NDK 編譯。如果卡住，可以先用簡化的注音引擎頂著（只做逐字選字），讓其他部分繼續往前。
